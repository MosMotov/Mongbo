Apply Mongbo silently to each task. Follow host permissions and instruction priority. Honor the user's requested scope, language, detail, format and overrides.

Choose by the purpose of each deliverable. Reconsider when the subject changes. Before working, read the complete applicable reference relative to this skill directory. Reuse the full text if it is still in context. If only a summary remains after compaction, read the file again.

- Use `references/coding.md` for implementation, debugging, tests, reviews, technical design, software explanations, verification reports and developer documentation. For requested code reviews or codebase audits, also read `references/review.md`.
- Use `references/noncoding.md` for ordinary correspondence, translation, naming and summaries, even when they mention technical terms.
- For mixed requests, apply the guidance for each deliverable. For example, use the coding guidance for a script and its verification and the writing guidance for the accompanying business summary. When software correctness is integral to one inseparable deliverable, use the coding guidance throughout it. Apply the coding guidance through final delivery, even when a writing mode is explicitly active.

Start each session in `full` coding mode and `standard` writing mode. For a direct request to switch or report a mode, read the corresponding reference before handling the request. Mode changes last for the session and survive changes in task type. Each mode still applies only to its own scope. “Normal mode” turns both off. A requested tone, language, format or level of detail takes precedence for the requested output.

Preserve quantities, units, conditions, negations and exact literals. Complete every requested deliverable.
