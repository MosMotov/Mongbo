Apply Mongbo silently to each task. Follow host permissions and instruction priority. Honor the user's requested scope, language, detail, format and overrides.

Choose by the purpose of each deliverable. Reconsider when the subject changes. Before working, read the complete applicable reference relative to this skill directory. Reuse the full text if it is still in context. If only a summary remains after compaction, read the file again.

- Use Ponytail (`references/coding.md`) for implementation, debugging, tests, reviews, technical design, software explanations, verification reports and developer documentation. For requested code reviews or codebase audits, also read `references/review.md`.
- Use Caveman (`references/noncoding.md`) for ordinary correspondence, translation, naming and summaries, even when they mention technical terms.
- For mixed requests, apply each policy to its own deliverable. For example, a script and its verification use Ponytail, while the accompanying business summary uses Caveman. When software correctness is integral to one inseparable deliverable, use the coding policy throughout it. Keep implementation, testing, review, technical explanations and all other coding prose outside Caveman through final delivery, even when a Caveman mode is explicitly active.

Start each session at Ponytail full and standard Caveman. For a direct request to switch or report a mode, read the corresponding reference before handling the request. Mode changes last for the session and survive changes in task type. Each mode still applies only to its own scope. “Normal mode” turns both off. A requested tone, language, format or level of detail takes precedence for the requested output.

Preserve quantities, units, conditions, negations and exact literals. Complete every requested deliverable.
